# agentrix-run

`agentrix-run` 用于从命令行或 CI 任务提交 Agentrix CI run。它适合放在流水线里，让
Agentrix 代理审阅 PR、总结变更、生成结构化输出，或者启动一个异步任务后再到 Agentrix
应用里查看结果。

它和主 `agentrix` 守护进程 CLI 是两套工具。`agentrix-run` 直接调用 Agentrix API 创建 CI
run，可以持续流式输出事件直到任务结束，也可以只创建任务后立即返回。

## 前置条件

- CI 任务里有 Node.js 20 或更高版本。
- 有一个能访问目标组织和仓库的 Agentrix API key。
- 能访问 Agentrix API。公有云 API 地址默认是 `https://agentrix.xmz.ai`。
- 目标仓库已接入 Agentrix。在 GitHub Actions 和 GitLab CI 中，`agentrix-run` 可以从 CI 环境变量自动识别当前仓库。
- 一个 runner ID。只有部署里配置了默认 cloud runner，或选择的 companion agent 已经绑定机器时，才可以省略。
- 如果使用 `--resume`，需要已有 task ID；此模式不需要仓库上下文或 runner ID。

建议把 API key 放到环境变量里：

```bash
export AGENTRIX_API_KEY=<your-api-key>
```

也可以通过 `--api-key` 显式传入 key。只有需要覆盖默认公有云 API 地址时，才需要传
`--base-url` 或设置 `AGENTRIX_BASE_URL`。

## 在 shell 中运行

CI 里建议固定 npm 包版本。当前包名是 `@agentrix/agentrix-run`。

```bash
npx --yes @agentrix/agentrix-run@0.2.0 \
  --agent codex \
  --prompt "Review this change and return one short summary sentence." \
  --response-mode stream \
  --runner-id cloud-default
```

如果不是在 GitHub Actions 或 GitLab CI 中运行，需要手动传仓库上下文：

```bash
npx --yes @agentrix/agentrix-run@0.2.0 \
  --agent codex \
  --prompt "Review this branch." \
  --repo '{"gitServerId":"github","owner":"xmz-ai","name":"agentrix"}' \
  --base-ref develop \
  --head-ref feature/demo \
  --pr-number 123 \
  --runner-id cloud-default
```

也可以向已有 task 追加消息。`agentrix-run` 会复用 task 的执行上下文；worker 在线时直接投递给 agent，worker 已退出时由后端恢复 task：

```bash
npx --yes @agentrix/agentrix-run@0.2.0 \
  --resume task-abc123 \
  --prompt "继续检查刚才失败的测试，并给出最终结论。" \
  --response-mode stream
```

## 响应模式

| 模式 | 行为 | 退出码 |
|---|---|---|
| `stream` | 创建 run，流式输出任务事件，等待终态后退出。这是默认模式。 | 只有最终状态为 `completed` 时返回 `0`；`failed`、`canceled` 或 `timeout` 会返回非零。 |
| `async` | 创建 run 并打印基础元数据，不等待任务完成。 | run 创建成功时返回 `0`。 |

使用 `--resume` 时，响应模式含义相同：`stream` 会在追加消息被接受后继续流式观察该 task，`async` 只确认消息已交给后端。

`stream` 模式下，stdout 会输出 JSON lines：

```json
{"type":"run.created","data":{"runId":"run-..."}}
{"type":"task.event","data":{}}
{"type":"run.completed","data":{"runId":"run-...","status":"completed","result":"...","detailUrl":"..."}}
```

`async` 模式下，stdout 会输出标准字段：

```text
run_id=run-abc123
status=queued
detail_url=https://agentrix.xmz.ai/tasks/task-abc123
```

如果后续 CI 步骤需要读取结果，用 `--result-file` 写入 JSON 文件：

```bash
npx --yes @agentrix/agentrix-run@0.2.0 \
  --agent codex \
  --prompt "Summarize this PR." \
  --result-file agentrix-result.json
```

结果文件格式如下：

```json
{
  "runId": "run-abc123",
  "status": "completed",
  "result": "Short summary text.",
  "structuredOutput": null,
  "detailUrl": "https://agentrix.xmz.ai/tasks/task-abc123"
}
```

## 结构化输出

通过 `--output-schema` 传入 JSON Schema 字符串。`agentrix-run` 会把对象 schema 规范化为严格结构化输出：对象节点会自动设置 `additionalProperties: false`，并把所有声明的属性加入 `required`。

```bash
npx --yes @agentrix/agentrix-run@0.2.0 \
  --agent codex \
  --prompt "Summarize this change." \
  --output-schema '{"type":"object","properties":{"summary":{"type":"string"},"risk":{"type":"string"}}}' \
  --result-file agentrix-result.json
```

规范化后的结构化输出会写入结果文件里的 `structuredOutput` 字段。GitHub Action 会把它暴露为
`structured-output-json` 输出。

## GitHub Actions

GitHub Actions 中推荐使用公开 action wrapper：

```yaml
name: Agentrix

on:
  pull_request:

jobs:
  agentrix:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - id: agentrix
        uses: xmz-ai/agentrix-run-action@v1
        with:
          api-key: ${{ secrets.AGENTRIX_API_KEY }}
          agent: codex
          prompt: >-
            Review this PR and return one short summary sentence.
          runner-id: cloud-default

      - name: Print result
        run: |
          echo "run id: ${{ steps.agentrix.outputs.run-id }}"
          echo "status: ${{ steps.agentrix.outputs.status }}"
          echo "detail url: ${{ steps.agentrix.outputs.detail-url }}"
          echo "result: ${{ steps.agentrix.outputs.result }}"
```

这个 action 会从 GitHub Actions 环境变量中自动识别仓库 owner、仓库名、ref、commit SHA、PR
base/head 分支、PR 编号、事件名和 workflow run URL。

### GitHub Action 输入

| 输入 | 必填 | 说明 |
|---|---:|---|
| `agent` | 是 | Agent ID 或名称，例如 `codex`。 |
| `prompt` | 是 | 发送给 Agentrix 的任务内容。 |
| `base-url` | 否 | Agentrix API 地址覆盖值。默认是 `https://agentrix.xmz.ai`。 |
| `api-key` | 是 | Agentrix API key。建议放在 GitHub Actions secrets 中。 |
| `title` | 否 | Agentrix 中显示的自定义任务标题。 |
| `output-schema` | 否 | 用于结构化输出的 JSON Schema 字符串。 |
| `repo` | 否 | 仓库 JSON 覆盖值。自动识别不够用时再传。 |
| `git-server-id` | 否 | 自动识别仓库时使用的 Git server ID，默认是 `github`。 |
| `response-mode` | 否 | `stream` 或 `async`。默认是 `stream`。 |
| `issue-number` | 否 | Issue 编号覆盖值。PR 编号会从事件 payload 中自动识别。 |
| `branch-name` | 否 | Task 分支名覆盖值。设置后 worker 会使用它，而不是自动生成的 `agentrix/<taskId>`。 |
| `timeout` | 否 | `stream` 模式下的等待超时时间，单位为秒。 |
| `capability-profile` | 否 | 传给执行层的 capability profile。 |
| `runner-id` | 通常是 | 指定 runner ID，例如 `cloud-*` 或 `machine-*`。只有部署里配置了默认 cloud runner，或选择的 companion agent 已经绑定机器时，才可以省略。 |

### GitHub Action 输出

| 输出 | 说明 |
|---|---|
| `run-id` | Agentrix run ID。 |
| `status` | `stream` 模式下的最终状态，或 `async` 模式下的创建状态。 |
| `detail-url` | Agentrix 任务 URL。 |
| `result` | 最终结果文本。`async` 模式下为空。 |
| `structured-output-json` | 最终结构化输出的 JSON 字符串。没有结构化输出时为 `null`。 |

## GitLab CI

在 GitLab CI 中，可以把下面这个隐藏 job 放进项目的 `.gitlab-ci.yml`，也可以放进你们自己维护的共享 CI 模板：

```yaml
.agentrix-run:
  image: node:20-alpine
  variables:
    AGENTRIX_RESPONSE_MODE: stream
  script:
    - |
      set -eu

      set -- \
        --agent "$AGENTRIX_AGENT" \
        --prompt "$AGENTRIX_PROMPT" \
        --response-mode "${AGENTRIX_RESPONSE_MODE:-stream}" \
        --runner-id "$AGENTRIX_RUNNER_ID"

      if [ -n "${AGENTRIX_TITLE:-}" ]; then
        set -- "$@" --title "$AGENTRIX_TITLE"
      fi
      if [ -n "${AGENTRIX_OUTPUT_SCHEMA:-}" ]; then
        set -- "$@" --output-schema "$AGENTRIX_OUTPUT_SCHEMA"
      fi
      if [ -n "${AGENTRIX_REPO:-}" ]; then
        set -- "$@" --repo "$AGENTRIX_REPO"
      fi
      if [ -n "${AGENTRIX_REF:-}" ]; then
        set -- "$@" --ref "$AGENTRIX_REF"
      fi
      if [ -n "${AGENTRIX_SHA:-}" ]; then
        set -- "$@" --sha "$AGENTRIX_SHA"
      fi
      if [ -n "${AGENTRIX_BASE_REF:-}" ]; then
        set -- "$@" --base-ref "$AGENTRIX_BASE_REF"
      fi
      if [ -n "${AGENTRIX_HEAD_REF:-}" ]; then
        set -- "$@" --head-ref "$AGENTRIX_HEAD_REF"
      fi
      if [ -n "${AGENTRIX_PR_NUMBER:-}" ]; then
        set -- "$@" --pr-number "$AGENTRIX_PR_NUMBER"
      fi
      if [ -n "${AGENTRIX_ISSUE_NUMBER:-}" ]; then
        set -- "$@" --issue-number "$AGENTRIX_ISSUE_NUMBER"
      fi
      if [ -n "${AGENTRIX_BRANCH_NAME:-}" ]; then
        set -- "$@" --branch-name "$AGENTRIX_BRANCH_NAME"
      fi
      if [ -n "${AGENTRIX_TIMEOUT:-}" ]; then
        set -- "$@" --timeout "$AGENTRIX_TIMEOUT"
      fi
      if [ -n "${AGENTRIX_CAPABILITY_PROFILE:-}" ]; then
        set -- "$@" --capability-profile "$AGENTRIX_CAPABILITY_PROFILE"
      fi
      if [ -n "${AGENTRIX_RESULT_FILE:-}" ]; then
        set -- "$@" --result-file "$AGENTRIX_RESULT_FILE"
      fi
      if [ -n "${AGENTRIX_BASE_URL:-}" ]; then
        set -- "$@" --base-url "$AGENTRIX_BASE_URL"
      fi

      npx --yes @agentrix/agentrix-run "$@"
```

然后在实际 pipeline job 里继承它：

```yaml
agentrix_review:
  extends: .agentrix-run
  variables:
    AGENTRIX_AGENT: codex
    AGENTRIX_PROMPT: Review this merge request and return one short summary sentence.
    AGENTRIX_RESPONSE_MODE: stream
    AGENTRIX_RUNNER_ID: cloud-default
```

把 `AGENTRIX_API_KEY` 保存为 masked CI variable。GitLab CI 自动识别会读取项目路径、commit
ref、commit SHA、MR source/target 分支、MR IID、job URL 和 pipeline URL。

### daemon webhook 触发的 pipeline

如果 GitLab pipeline 是由 Agentrix daemon webhook bridge 触发的，daemon 会把 GitLab webhook
规范化成 `AGENTRIX_EVENT_NAME` 和 `AGENTRIX_EVENT_ACTION`，并设置 issue/MR/pipeline/comment
相关变量。此时 GitLab 标准变量仍然可用，`agentrix-run` 会用 `CI_PROJECT_PATH`、
`CI_COMMIT_REF_NAME` 和 `CI_COMMIT_SHA` 自动识别仓库和 commit。

建议每类 webhook 单独写 job，用 `rules` 限制它只响应 daemon 触发：

```yaml
agentrix_issue_triage:
  extends: .agentrix-run
  rules:
    - if: '$AGENTRIX_TRIGGER_SOURCE == "agentrix_daemon_webhook" && $AGENTRIX_EVENT_NAME == "issues"'
      when: on_success
    - when: never
  variables:
    AGENTRIX_AGENT: codex
    AGENTRIX_RESPONSE_MODE: stream
    AGENTRIX_RUNNER_ID: cloud-default
    AGENTRIX_TITLE: "Issue #$AGENTRIX_ISSUE_NUMBER: $AGENTRIX_EVENT_ACTION"
    AGENTRIX_PROMPT: >-
      Review GitLab issue #$AGENTRIX_ISSUE_NUMBER in this repository.
      Event action: $AGENTRIX_EVENT_ACTION.
      Issue title: $AGENTRIX_ISSUE_TITLE.
      Decide whether this needs agent work, and return a short triage summary.
```

MR review job：

```yaml
agentrix_mr_review:
  extends: .agentrix-run
  rules:
    - if: '$AGENTRIX_TRIGGER_SOURCE == "agentrix_daemon_webhook" && $AGENTRIX_EVENT_NAME == "pull_request" && ($AGENTRIX_EVENT_ACTION == "opened" || $AGENTRIX_EVENT_ACTION == "reopened" || $AGENTRIX_EVENT_ACTION == "synchronize")'
      when: on_success
    - when: never
  variables:
    AGENTRIX_AGENT: codex
    AGENTRIX_RESPONSE_MODE: stream
    AGENTRIX_RUNNER_ID: cloud-default
    AGENTRIX_TITLE: "MR !$AGENTRIX_PR_NUMBER review"
    AGENTRIX_PROMPT: >-
      Review GitLab merge request !$AGENTRIX_PR_NUMBER.
      Source branch: $AGENTRIX_HEAD_REF.
      Target branch: $AGENTRIX_BASE_REF.
      Return concise findings and suggested fixes.
```

评论 job。daemon 默认转发 supported 非 system 评论；如果只想响应命令，可以在 job 规则里加 `AGENTRIX_COMMENT_COMMAND == "true"`：

```yaml
agentrix_comment_command:
  extends: .agentrix-run
  rules:
    - if: '$AGENTRIX_TRIGGER_SOURCE == "agentrix_daemon_webhook" && $AGENTRIX_EVENT_NAME == "issue_comment" && $AGENTRIX_COMMENT_COMMAND == "true"'
      when: on_success
    - when: never
  variables:
    AGENTRIX_AGENT: codex
    AGENTRIX_RESPONSE_MODE: stream
    AGENTRIX_RUNNER_ID: cloud-default
    AGENTRIX_TITLE: "Agentrix comment command"
    AGENTRIX_PROMPT: >-
      Handle this GitLab comment command.
      Target type: $AGENTRIX_SUBJECT_KIND.
      Issue: $AGENTRIX_ISSUE_NUMBER.
      Merge request: $AGENTRIX_PR_NUMBER.
      Comment: $AGENTRIX_COMMENT_BODY
```

Pipeline failed 诊断 job。Pipeline webhook 会作为 `workflow_run` 事件转发，包括由 trigger token 创建的 pipeline：

```yaml
agentrix_pipeline_failed:
  extends: .agentrix-run
  rules:
    - if: '$AGENTRIX_TRIGGER_SOURCE == "agentrix_daemon_webhook" && $AGENTRIX_EVENT_NAME == "workflow_run" && $AGENTRIX_EVENT_ACTION == "completed" && $AGENTRIX_WORKFLOW_RUN_CONCLUSION == "failure"'
      when: on_success
    - when: never
  variables:
    AGENTRIX_AGENT: codex
    AGENTRIX_RESPONSE_MODE: stream
    AGENTRIX_RUNNER_ID: cloud-default
    AGENTRIX_TITLE: "Pipeline $AGENTRIX_PIPELINE_ID failed"
    AGENTRIX_PROMPT: >-
      Diagnose failed GitLab pipeline $AGENTRIX_PIPELINE_ID.
      Ref: $AGENTRIX_REF.
      SHA: $AGENTRIX_SHA.
      Pipeline URL: $AGENTRIX_PIPELINE_URL.
      Explain the likely cause and propose the smallest fix.
```

其他常见分流写法：

```yaml
agentrix_issue_closed:
  extends: .agentrix-run
  rules:
    - if: '$AGENTRIX_TRIGGER_SOURCE == "agentrix_daemon_webhook" && $AGENTRIX_EVENT_NAME == "issues" && $AGENTRIX_EVENT_ACTION == "closed"'
      when: on_success
    - when: never
  variables:
    AGENTRIX_AGENT: codex
    AGENTRIX_PROMPT: "Summarize the closing state of GitLab issue #$AGENTRIX_ISSUE_NUMBER."
    AGENTRIX_RESPONSE_MODE: async
    AGENTRIX_RUNNER_ID: cloud-default
```

不要只依赖 `CI_PIPELINE_SOURCE` 区分来源。daemon 触发的 pipeline 在 GitLab 中通常也是 trigger
pipeline，应优先用 `AGENTRIX_TRIGGER_SOURCE`、`AGENTRIX_EVENT_NAME` 和
`AGENTRIX_EVENT_ACTION` 做分流。

## CLI 选项

| 选项 | 必填 | 说明 |
|---|---:|---|
| `--agent <agent>` | 新建 run 时必填 | Agent ID 或名称。 |
| `--resume <task-id>` | 否 | 向已有 task 追加一条 `--prompt` 消息。设置后不创建新的 CI run，也不需要 `--agent`。 |
| `--prompt <prompt>` | 是 | 发送给 Agentrix 的任务内容。 |
| `--title <text>` | 否 | Agentrix 中显示的自定义任务标题。 |
| `--repo <json>` | 通常自动识别 | 仓库 JSON 对象。必须包含 `gitServerId`，并且包含 `serverRepoId` 或同时包含 `owner` 与 `name`。 |
| `--output-schema <json>` | 否 | 用于结构化输出的 JSON Schema 字符串。对象 schema 会被规范化为严格输出。 |
| `--ref <ref>` | 否 | 本次 run 的 Git ref。会覆盖 CI 自动识别的 ref。 |
| `--sha <sha>` | 否 | 本次 run 的 commit SHA。会覆盖 CI 自动识别的 SHA。 |
| `--base-ref <ref>` | 否 | PR 或 MR 的 base 分支。 |
| `--head-ref <ref>` | 否 | PR 或 MR 的 head 分支。 |
| `--branch-name <name>` | 否 | Task 分支名覆盖值。设置后 worker 会使用它，而不是自动生成的 `agentrix/<taskId>`。 |
| `--pr-number <number>` | 否 | PR 或 MR 编号。必须是正整数。 |
| `--issue-number <number>` | 否 | Issue 编号。必须是正整数。 |
| `--response-mode <stream\|async>` | 否 | `stream` 等待完成；`async` 只创建 run。默认是 `stream`。 |
| `--timeout <seconds>` | 否 | `stream` 模式下的等待超时时间。默认是 `1800`。必须是正整数。 |
| `--capability-profile <name>` | 否 | 传给执行层的 capability profile。 |
| `--runner-id <cloud-id\|machine-id>` | 通常是 | 指定 runner，例如 `cloud-default` 或 `machine-...`。只有部署里配置了默认 cloud runner，或选择的 companion agent 已经绑定机器时，才可以省略。 |
| `--result-file <path>` | 否 | 把 run 结果 JSON 写入指定路径。 |
| `--base-url <url>` | 否 | Agentrix API 地址覆盖值。默认是 `https://agentrix.xmz.ai`；优先级高于 `AGENTRIX_BASE_URL`。 |
| `--api-key <api-key>` | 未设置 `AGENTRIX_API_KEY` 时必填 | Agentrix API key。推荐通过环境变量或 CI secret 传。 |
| `--metadata <key=value>` | 否 | 给 run 添加 metadata。可以重复传多次。 |
| `--help` | 否 | 打印命令帮助。 |

## 仓库 JSON

`--repo` 接收以下形状的 JSON 对象：

```json
{
  "gitServerId": "github",
  "owner": "xmz-ai",
  "name": "agentrix"
}
```

也可以通过服务端仓库 ID 标识仓库：

```json
{
  "gitServerId": "github",
  "serverRepoId": "repo-abc123"
}
```

检测到 CI provider 时，`--repo` 中的显式字段会覆盖自动识别出来的字段。

## 环境变量

| 变量 | 使用方 | 说明 |
|---|---|---|
| `AGENTRIX_BASE_URL` | CLI、GitHub Action 子进程、GitLab 模板 | 可选的 Agentrix API 地址覆盖值。默认是 `https://agentrix.xmz.ai`；传入 `--base-url` 时会被覆盖。 |
| `AGENTRIX_API_KEY` | CLI、GitHub Action 子进程、GitLab 模板 | API key，会作为 bearer token 使用。传入 `--api-key` 时会被覆盖。 |
| `AGENTRIX_GIT_SERVER_ID` | CI 自动识别 | 自动识别仓库时使用的 Git server ID。GitHub Actions 默认是 `github`，GitLab CI 默认是 `gitlab`。 |
| `AGENTRIX_EVENT_NAME` | CI 自动识别 | 覆盖自动识别的事件名。 |
| `AGENTRIX_EVENT_ACTION` | CI 自动识别 | 覆盖自动识别的事件动作。 |
| `AGENTRIX_JOB_URL` | CI 自动识别 | 覆盖自动识别的 job URL。 |
| `AGENTRIX_RUN_URL` | CI 自动识别 | 覆盖自动识别的 workflow 或 pipeline URL。 |
| `AGENTRIX_ISSUE_NUMBER` | GitLab CI 自动识别 | GitLab CI 中的 Issue 编号兜底值。 |
| `AGENTRIX_AGENT` | GitLab 模板 | Agent ID 或名称。 |
| `AGENTRIX_PROMPT` | GitLab 模板 | 任务内容。 |
| `AGENTRIX_TITLE` | GitLab 模板 | 自定义任务标题。 |
| `AGENTRIX_OUTPUT_SCHEMA` | GitLab 模板 | 用于结构化输出的 JSON Schema 字符串。 |
| `AGENTRIX_REPO` | GitLab 模板 | 仓库 JSON 覆盖值。 |
| `AGENTRIX_REF` | GitLab 模板 | Git ref 覆盖值。 |
| `AGENTRIX_SHA` | GitLab 模板 | Commit SHA 覆盖值。 |
| `AGENTRIX_BASE_REF` | GitLab 模板 | Base 分支覆盖值。 |
| `AGENTRIX_HEAD_REF` | GitLab 模板 | Head 分支覆盖值。 |
| `AGENTRIX_PR_NUMBER` | GitLab 模板 | PR 或 MR 编号覆盖值。 |
| `AGENTRIX_BRANCH_NAME` | CLI、GitLab 模板 | Task 分支名覆盖值。传入 `--branch-name` 时会被覆盖。 |
| `AGENTRIX_RESPONSE_MODE` | GitLab 模板 | `stream` 或 `async`。模板中默认是 `stream`。 |
| `AGENTRIX_TIMEOUT` | GitLab 模板 | 等待超时时间，单位为秒。 |
| `AGENTRIX_CAPABILITY_PROFILE` | GitLab 模板 | Capability profile。 |
| `AGENTRIX_RUNNER_ID` | GitLab 模板 | Runner ID。上面的模板要求设置这个变量。 |
| `AGENTRIX_RESULT_FILE` | GitLab 模板 | 结果 JSON 文件路径。 |

`agentrix-run` 还会读取 GitHub Actions 和 GitLab CI 的标准环境变量。在这两类 CI provider
里，通常不需要手动传 refs、SHA 或 PR/MR 编号。
