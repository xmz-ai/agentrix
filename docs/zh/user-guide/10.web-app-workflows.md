# Web 应用工作流

当你想从浏览器、桌面应用内嵌窗口或移动端发起任务、查看进度、审阅结果时，使用 Agentrix Web 应用。Web 应用和 CLI daemon 共用同一套后端、机器、仓库和 agents。

## 主要区域

| 区域 | 用途 |
|---|---|
| **Chats** | 与一个或多个 agents 进行长期对话 |
| **Tasks** | 聊天或仓库工作区里的具体工作项 |
| **Repos** | 以仓库为中心处理 inbox、issues、MRs 和任务 |
| **Agents** | 查看联系人和已安装 agents |
| **Explore** | Agent Community marketplace，用于 agents 和 skills |
| **Settings** | 账户、计费、机器、API keys 和偏好设置 |

在平板和桌面布局中，侧边栏可以折叠或展开。移动端会把每个区域作为独立页面打开。

## 聊天与群聊

当工作比较探索性，或者一件事会拆成多个任务时，用聊天更合适。打开 **Chats**，选择已有聊天，或从侧边栏创建新的 group chat。

在聊天里可以：

- 给选中的 agent 或 group 继续补充指令。
- 在本地机器、cloud runner 或 private cloud runner 之间切换执行环境。
- 查看对话中产生的任务历史、artifacts 和前端预览。
- 在 composer 支持的情况下附加文件。
- 删除不再需要的旧聊天。

如果某个聊天里有正在执行的任务，打开聊天时会直接进入该任务，方便查看实时事件流。

## 创建任务

当你希望 agent 完成一个明确变更时，使用任务 composer。

1. 选择 agent。
2. 选择任务运行位置：
   - **Local machine** 适合需要本地工具、凭据或文件系统的任务。
   - **Cloud 或 Private Cloud** 适合团队管理的共享 runner。
3. 如果任务要修改代码，选择仓库。
4. 在界面提供时选择分支和工作目录。
5. 写清楚期望结果和约束。
6. 需要时打开 advanced options 修改执行模式。
7. 提交任务并查看事件流。

### 执行模式

| 模式 | 适用场景 |
|---|---|
| **Loop** | 希望 agent 持续通过工具调用、反馈和验证推进，直到得到终态结果。 |
| **One-shot** | 希望得到一次性回复或一次有限处理，不需要长时间自主循环。 |

实现功能、排查问题和重构时通常使用 Loop。简短分析、摘要和范围很小的 review 更适合 One-shot。

## 审阅 Agent 输出

任务详情页会把审阅所需的信息放在一起。

- **History** 显示用户消息、agent 消息、工具日志、审批请求和状态更新。
- **Artifacts** 显示变更文件、生成文件、diff、commit 和附件输出。
- **Preview** 在 Web 平台上打开可预览的前端产物。
- **Heartbeat** 和状态指示能帮助判断 worker 是否还在线。

对生成文件，项目查看器可以展示源码、diff 和预览。它支持常见代码与文本文件、图片、SVG、视频、Markdown、HTML、PDF、Word、Excel 和 PowerPoint。具体预览能力取决于当前平台。

## Ask-User 流程

有些任务会暂停并向用户提问。看到 ask-user 卡片时，在任务详情页回复即可，worker 会在收到回复后继续执行。这个流程适合产品决策、无需暴露凭据的澄清，以及高风险操作前的确认。

## 重试与归档

失败任务在后端能够恢复上下文时，会显示可重试信息。归档会话会从活跃任务列表中移出，但历史仍可查看。归档适合已完成或放弃的工作，不适合正在排查的问题。

## 分享任务

任务分享会生成带明确权限的链接。分享时只开放对方需要的信息，尤其是本地任务，因为其中可能包含仓库上下文、日志或 artifacts。

在安全分享功能上线前创建的旧本地任务可能无法分享。如果应用提示旧任务不支持安全分享，请新建任务后再分享。

## 实用 Prompt 格式

一个清楚的任务 prompt 通常包含仓库区域、期望变更、验证命令和验收标准：

```text
Update the billing settings screen so users can see the active package expiry date.
Follow the existing Settings item style.
Run app typecheck after the change.
Acceptance: active packages show amount and expiry, empty state is unchanged.
```

处理仓库 issue 时，优先从仓库工作流进入 issue 再创建任务，这样应用可以自动附带 issue 元数据、评论和引用信息。
